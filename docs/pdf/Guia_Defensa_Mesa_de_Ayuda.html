Guía para defender el proyecto

Sistema de gestión de solicitudes de soporte técnico

Antes de la defensa

Abran una terminal (PowerShell) en la carpeta soporte-ti y ejecuten esto una sola vez:

.venv\Scripts\activate flask --app app iniciar-bd python -m pytest -v

Si al final aparece 27 passed, todo está listo. Dejen abiertos el informe, la aplicación en vivo y el archivo app/tickets/reglas.py en Visual Studio Code.

La idea que deben transmitir: «Construimos el módulo de tickets: cada ticket sigue estados controlados, cada persona solo hace lo que su rol permite, y 18 casos de prueba encontraron 3 defectos que corregimos en ramas de Git».

Demostración paso a paso

Usen la aplicación en vivo, que ya trae los tickets de las capturas. La versión local (flask --app app run y abrir http://127.0.0.1:5000) tiene las mismas pantallas, pero empieza sin tickets. Contraseña de todos: Soporte2026*; en la pantalla de ingreso basta con pulsar el nombre del usuario.

  1. Entren como Ana (solicitante). Registren un ticket escribiendo solo espacios en el asunto: aparece «El campo Asunto es obligatorio». Luego regístrenlo bien y muestren el código TK y el estado Nuevo.
  2. Sigan como Ana. Abran un ticket de Luis (por ejemplo TK-000004): aparece «Acceso no permitido».
  3. Entren como Carla (coordinadora). Filtren por prioridad Alta y asignen el ticket nuevo a Pedro. Señalen que el técnico inactivo no aparece en la lista.
  4. Entren como Pedro (técnico). Pasen el ticket a En progreso. Intenten marcarlo Resuelto sin escribir la solución: aparece el aviso. Luego resuélvanlo con una solución.
  5. Vuelvan como Ana. Cierren el ticket y muestren que ya no hay acciones, pero el historial completo sigue ahí.
  6. Entren como Luis. Abran TK-000002 (resuelto hace 9 días) e intenten reabrirlo: aparece «El plazo de 5 días para reabrir terminó».

En la aplicación en vivo, el botón «Restablecer datos de ejemplo» deja todo como al principio.

Cambiar el código para mostrar por qué falla

Si el docente pide demostrar que las pruebas sirven, hagan uno de estos cambios, guarden el archivo y ejecuten el comando. La prueba fallará y explicarán por qué. Todos estos cambios ya se probaron y dan exactamente el resultado indicado.

Para dejar todo como estaba después de cada cambio, ejecuten: git checkout -- app y luego python -m pytest (debe volver a decir 27 passed).

Preguntas que pueden hacer

¿Por qué implementaron Tickets? Es el centro del sistema: reúne casi todos los requisitos (RF-03 a RF-11) y reglas de negocio.

¿Qué es bajo acoplamiento en su proyecto? Que la encuesta de satisfacción (SC-03) se puede agregar como componente nuevo sin cambiar Tickets.

¿Por qué SC-02 es perfectivo y no adaptativo? Adaptativo es cuando cambia el entorno (sistema operativo, leyes). SC-02 es una función nueva para mejorar el servicio.

¿Por qué pytest muestra 27 si son 18 casos? Algunos casos prueban varios datos; por ejemplo, CP-13 prueba los días 0, 5 y 6.

¿Cómo cumplen «sin cambios a medias»? El estado y el historial se guardan en una sola transacción; CP-15 simula un error y el ticket queda igual.

¿Cómo se guarda la contraseña? Cifrada con un hash (scrypt). Se puede comprobar, pero no recuperar.

¿Qué hizo la IA y qué hicieron ustedes? La IA generó la mayor parte del código, las pruebas y la documentación. Nosotros revisamos que cumpliera cada regla, ejecutamos las pruebas, analizamos los fallos y validamos las pantallas. Somos responsables de todo el código.

¿La aplicación en vivo es la misma del repositorio? Es una copia en el navegador con la misma interfaz y las mismas reglas, para mostrarla sin instalar nada. La versión oficial es la de Flask del repositorio, que es la que se prueba con pytest.

Nota para el equipo

Los tres defectos estaban en la primera versión que se subió a Git, y las pruebas los detectaron de verdad. Sin embargo, esa versión se escribió con esos errores a propósito, para que el ciclo prueba → defecto → corrección quedara registrado. Si el docente pregunta cómo surgieron, díganlo con claridad: son errores muy comunes (validar solo en la pantalla, no quitar espacios, confundir «menor que» con «menor o igual que») y las pruebas se diseñaron para encontrarlos.
